# Multisig IDL (RFP-005 U.4)

`msig.idl.json` describes the program's instructions (`create`, `execute`, `queue`, `execute_queued`, `spend`), the `Multisig` state
account, every borsh type reachable from `Instruction`, the 22 error codes and the public constants.

- Generated by `python3 scripts/gen_idl.py` from `crates/msig-core/src/lib.rs`; the lee_core types it
  embeds (AccountId, Actor, keys) are listed by hand and asserted against `vendor/lez`.
- Drift check: `python3 scripts/gen_idl.py --check` (exit 1 if the committed file differs). Run in CI.
- SPEL load test: `idl/spel-check/run.sh` fetches SPEL's `idl.rs` (logos-co/spel `c6f73ce`, serde only)
  and deserialises the file with the real `SpelIdl` structs. Run in CI.

## Caveats

- SPEL-format JSON only. SPEL's own generator (`#[lez_program]`) and client generator target
  lee_core v0.2.5; this program is a LEZ v0.4 actor program (`actor_entrypoint!`), so neither was run.
  Generator and client interop is unproven; only the JSON schema is checked.
- Wire format is `borsh(Instruction)` with the enum tag (`variant_index`, u8), not SPEL's
  `sha256("global:name")` discriminator.
- The multisig account's PDA seed is `sha256(pad32("LEZ-MSIG/v1/seed") || sha256(borsh(cfg)) || salt)`,
  a hash of the config, not an argument path, so the IDL lists no `pda.seeds`; a SPEL client cannot
  derive the address from the IDL alone. The visibility `private_pda` is a free-form extension.
- Extra keys (`variant_index`, `doc`, `constants`, `notes`) are outside SPEL's schema and ignored by it.
